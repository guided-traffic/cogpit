## Fixtures

- **Recorded objects** are real API responses with names, namespaces, IPs and UIDs replaced by
  synthetic values. Never commit objects from a real cluster unscrubbed: they carry internal
  hostnames, registries and sometimes credentials in annotations or environment variables.
- **Clusters** are created by the tests (`kind`, envtest), never borrowed from a developer's
  kubeconfig. Tests must not read `~/.kube/config` or any other file of `~/.kube` (the default synced
  folder and the files `$KUBECONFIG` names are injected: `engine.WithDefaultFolder` and
  `engine.WithSessionFiles` take temporary paths and the engine reads no environment variable, the shell's sync picker
  opens in one, `kubeconfigUI.startDir`); `kind` writes its kubeconfig to a temporary
  file (`--kubeconfig`), never into the user's.
- **Signing material** (2026-10-15, [D-50](decisions.md#d-50-kubectls-signature-check)): the real
  `.sha256`, `.sig`, `.cert` and Rekor search answer of kubectl 1.36.1 and 1.37.1 (darwin/arm64) in
  [`kubectl/testdata`](../../internal/kubectl/testdata/), public material every download reads,
  verified offline against the embedded trusted root and changed field by field for the refusals;
  everything else is signed and logged by a sigstore instance of the test's own
  ([`testkit/sigstoretest`](../../internal/testkit/sigstoretest/sigstoretest.go)), whose Rekor
  search `testkit.KubectlReleases` serves beside its releases. No test but the opt-in live one
  reaches sigstore.
- **API request counting:** tests wrap the client's transport in a counting round-tripper and
  assert the requests a scenario may cost.
- **The real engine under the window** (2026-10-13): the window's tests may not import the cache
  or the cluster layer (depguard's `l4-ui`), so a test that runs the real engine and commands under
  the shell over an in-memory source takes its connector from
  [`testkit/enginekit`](../../internal/testkit/enginekit/enginekit.go) (`MemoryConnector`, and
  `FluxRecorder` for the Flux actions' patches): the Flux section's tests and renders
  ([`flux_test.go`](../../internal/ui/fyneui/flux_test.go)).

## Asynchronous results

CI runs on slower, loaded machines (self-hosted pods that share a 16-CPU machine, a three-core macOS runner); a test that
passes here because goroutines usually finish in some order fails there. The rules the flaky tests
of 2026-10-12 broke:

- **Wait for the result, never for time.** Poll the condition with a deadline
  (`testkit.WaitFor`, `waitTable`, a UI test's `q.until`), or gate the step that has to come
  first. A bare sleep is neither a wait nor a proof that something did not happen.
- **Wait for the thing you assert, not for something that usually comes with it.** A synced
  events table is not a synced Workloads Overview (its kinds list on their own); a recorded
  `Dispatch` call is not its UI state change (the fake records the call first); an `EventKinds`
  after a change may be one still on its way from before it.
- **Request budgets take their baseline once the cache is settled.** A list-then-watch
  informer reports synced after its list and opens its watch only after that, and a view or
  drawer acquires its informers (endpoint slices of services, the drawer's events) without
  waiting for them. On a `MemorySource`, wait for `testkit.Settled(cache, src)` (every informer
  synced and its watch open) before reading the counters, and again before comparing them; on
  the fake API server, wait for `OpenWatches`. A budget stays at what it is: an extra request
  after a settled baseline is a finding, not noise.
- **The window's own reports move the engine's state too.** The navigator reports its keyboard row a
  debounce after the kinds came (`ui.setNavigatorRow`, D-51), so a test that waits for "the last
  state" compares the shell with the engine's revision read at every check, never with one read
  once after its own changes: on a slow runner the report lands later and a revision read once is
  never reached again (`TestEngineEventsWithoutRaces`, CI, 2026-10-18).
- **A time the window shows comes from the shell's clock** (`sh.now`, `fixedNow` in the tests),
  never from `time.Now()`: a test that asserts the text then pins it exactly. An edit tab's
  "loaded at" read the wall clock, and a check that the text holds no "41" (the resourceVersion,
  D-85) failed whenever the minute or the second was 41 (`TestEditTabSaveReviewsThenApplies`, CI,
  2026-10-18).
- **State a test sets on a fake while a shell runs goes through the fake's lock** (`update`),
  and a test that starts a second shell on the same fake stops the first one.
- **`select` picks at random among ready cases.** Code that honours a cancelled context
  checks `ctx.Err()` itself, before the work and after it; a `select` between a result and
  `ctx.Done()` alone returns the result about half the time when both are ready (the
  port-forward dial on CI, main 7e01d03, 2026-10-12).
  `TestDialPortForwardCancelledWhileDialling` forces that interleaving with a context that is
  cancelled from its second `Err` call on.
- **A simulated second process stays alive until the test ends.** An object the test no longer
  uses can be collected, and its finalizers run: a journal standing in for another Cogpit lost
  its owner file's lock that way and looked ended (`TestDrainsOfAnotherProcess`, 2026-10-12). Keep
  it with `runtime.KeepAlive`, and force the collection (`runtime.GC()`) to make such a failure
  deterministic.
- **The machine's environment is not the test's.** CI's self-hosted runners are pods (2026-10-13):
  `KUBERNETES_SERVICE_HOST`, `KUBERNETES_SERVICE_PORT` and a service account token made client-go
  take the pod's namespace as a context's default, and the pods set no `SHELL`, so the local
  terminal fell back to a zsh their image lacks. `make`'s `TEST_ENV` removes the in-cluster
  variables beside `KUBECONFIG=/dev/null`, and CI sets `SHELL`; a test that needs a shell or a
  namespace names it.
- **Reproduce before fixing.** Run the test many times under load (`go test -race -count=50
  -cpu 1,2` while other packages' tests run), or make the suspected window wide on purpose: a
  short delay in a fake source's List and Watch, or in a fake's handler, turns a rare
  interleaving into a deterministic one. A product race gets a regression test that forces the
  interleaving (a gated source, a held mutex), not one that hopes to hit it.

## Before a pull request

Locally, check only what the change touches (owner, 2026-10-12); CI runs every tier above on every
push and is the full gate ([`AGENTS.md`](../../AGENTS.md#5-before-you-finish-a-task),
[releasing › CI](releasing.md#ci)):

```sh
GOFLAGS=-p=4 go build ./...
GOFLAGS=-p=4 go vet ./internal/<pkg>/...    # the packages you touched
GOFLAGS=-p=4 go test ./internal/<pkg>/...   # their tests, without -race
go test -race ./internal/<pkg>/...          # only when the change is about concurrency (cache, journals, terminal)
make test-kind        # only when you need the cluster tier before CI; needs make kind-up
make test-kind-drain  # likewise for cordon and drain; needs make kind-drain-up (a separate cluster)
make test-envtest     # the envtest tier; fetches its pinned binaries first (no Docker)
make scorecard        # only when a change moves a budget: on a quiet machine, then commit docs/parity/scorecard.md
```
