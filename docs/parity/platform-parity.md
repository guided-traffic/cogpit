# Platform parity: systems, packages, authentication and tools

> **Target:** Lens Desktop 2026.10.51501

Where and how Cogpit runs compared with Lens Desktop: operating systems and architectures, packages
and updates, cluster authentication, Kubernetes versions and the external tools it depends on.
Method: [`README.md`](README.md).

**Sources.** Lens Desktop: [install](https://docs.lenshq.io/k8slens/getting-started/install-lens/),
[technical FAQ](https://docs.lenshq.io/faq/technical-faq/),
[preferences](https://docs.lenshq.io/k8slens/using-lens/preferences/), its update feeds
(`latest.yml`, `latest-mac.yml`, `latest-linux.yml` on `downloads.k8slens.dev`) and the
2026.10.51501 release notes. Cogpit's ecosystem facts: [decisions](../developer/decisions.md).

**Summary (counted by `make parity`):** 21 of 35 rows partial, none done; eight more are not
targets or have nothing to build, among them the cloud providers' credential plugins and account
integrations ([D-9](../developer/decisions.md#d-9-scope-against-lenss-paid-and-vendor-features)).
Releases ship for macOS (arm64), Linux (amd64, arm64) and Windows (x64)
([D-7](../developer/decisions.md#d-7-language-and-platforms)). Partial: the macOS disk image, the
Linux deb with Cogpit's APT repository, the Windows setup, and their update notice, one-click
update, Stable channel, signed update manifest and checksums (9 of 13 package rows); client
certificates, bearer tokens, exec credential plugins, users limited to some namespaces, the
per-cluster proxy, `proxy-url` and the kubeconfig's TLS settings (7 of 10 authentication rows);
Kubernetes 1.37, older clusters, kinds newer than the client libraries, the sidebar following the
served APIs, and `kubectl` for terminals. Remaining: the universal macOS app, the cask, an SBOM and
signed checksums ([G14](gaps.md#g14-packaging-signing-and-updates-macos)); Authenticode, an ARM64
setup, winget and Scoop, the other Linux formats, and `cogpit://` links and Start at login on
Windows and Linux ([G22](gaps.md#g22-windows-and-linux)); the missing authentication rows
([G2](gaps.md#g2-cluster-connection-and-authentication)).

## Cluster authentication and connectivity

How kubeconfig credentials reach the API server
([security › credentials](../security/credentials.md)). Lens Desktop connects through "a series of
internal proxies" with a background HTTP proxy on a free local port, and its FAQ therefore requires
`localhost` to resolve to `127.0.0.1` ([technical FAQ](https://docs.lenshq.io/faq/technical-faq/)).
Cogpit connects directly with client-go from the process that holds the credentials, so that
requirement does not apply.
